# ГИС-экскурсовод — плагин QGIS

Пишете название туристического объекта — **«вулкан Горелый»** или **«Московский Кремль»** —
и плагин сам:

1. **Находит объект** и его координаты (OpenStreetMap / Nominatim, при неудаче — Википедия).
2. **Определяет тип туризма.** Вулкан, пещера, водопад — **природный**; объект среди плотной
   городской застройки (Кремль, музей, собор) — **городской**. Можно выбрать и вручную.
   От типа зависит всё остальное: какие объекты искать, нужен ли рельеф и животные,
   какие советы давать и как устроен отчёт.
3. **Подбирает попутные объекты** в прямоугольной зоне ±1…30 км — **самые популярные**
   (по просмотрам статей Википедии за месяц). Перед поиском уточняет радиус: для природы
   обычно ±10…20 км, для города ±1…3 км. Найденное — в выпадающем списке с галочками.
   Если нашлось меньше, чем нужно, предложит расширить зону; если сервис не ответил —
   так и скажет, а не покажет пустой список.
   Пока вы ставите галочки, плагин **сразу прикидывает время**: успеете ли за один день.
   Кнопки **вариантов** — «Полдня», «Полный день», «2 дня с ночёвкой» — сами отмечают
   объекты, которые помещаются в это время (с учётом светового дня на дату поездки).
   Объекты, стоящие рядом и связанные друг с другом (Царь-пушка и Царь-колокол в Кремле,
   кратер и вершина вулкана), **объединяются в одну остановку**.
4. **Строит маршрут.** Откуда ехать — региональный центр, а если в регионе есть город больше
   200 тыс. жителей ближе к объекту — от него (или от места, которое вы укажете).
   Дальше — оптимальный порядок обхода и пеший маршрут: по тропам и улицам, а где троп
   нет — по рельефу (самый быстрый для пешехода путь в обход склонов круче 35°).
   Если рядом есть **маркированная тропа** (OSM: маршруты hiking/foot), маршрут идёт по ней,
   когда она не длиннее обычного пути больше чем на четверть. Путь по рельефу **обходит
   озёра, реки и ледники**, а болота — по возможности.
   В городе прогулка начинается от ближайшей станции метро/железной дороги.
5. **Если за день не успеть**, разбивает маршрут по дням и предлагает **три ближайших
   варианта ночлега** — дорогой, средний и бюджетный (класс — по типу и звёздам из
   OpenStreetMap; цены уточняйте у владельцев).
6. **Проверяет сезон и доступность**: часы работы музеев и ООПТ на дату поездки
   (opening_hours из OSM), сезонные и зимние дороги, ледовые переправы, перевалы,
   ограничения проезда — всё это в разделе отчёта «Сезон и доступность».
7. **Рисует три фирменные карты** (макеты QGIS, их можно править):
   * **обзорная карта региона** — граница, региональный центр, крупные города,
     населённые пункты рядом с объектом, дорога, а для огромных регионов — врезка «Подъезд»;
   * **карта-схема маршрута** — пронумерованные точки, маршрут со стрелками направления,
     таблица точек, рельеф или подложка;
   * **карта-схема фотографий** — где сделан каждый снимок; номера те же, что в отчёте.

   Близко стоящие точки и фото раздвигаются «розеткой» вокруг своего места — номера не
   налезают друг на друга. Зона поиска на карты не выносится.
8. **Делает отчёт в HTML и PDF** в одном фирменном стиле: описание объекта, как добраться
   (дорога по трассам или метро и автобусы), маршрут по участкам и профиль высот,
   описания объектов (в городе — часы работы, вход, сайт), что надеть и сколько взять
   воды и еды по прогнозу погоды, где поесть, безопасность (ООПТ, медведи, клещи,
   газы у фумарол), фотографии Викисклада с подписями авторов, для природы — кого можно
   встретить и заметки натуралистов iNaturalist.
   **В HTML карты интерактивные** (Leaflet встроен в файл): масштаб колёсиком, область
   ограничена окрестностями маршрута, по щелчку на номер фото — снимок и переход к нему
   в отчёте. Фирменный лист для печати раскрывается под каждой картой. Подложке нужен
   интернет; без него маршрут и точки всё равно видны.
9. **Готовит трек GPX и KML** для навигатора: трек хранится в памяти, пока открыто окно
   плагина, и сохраняется кнопкой «Скачать трек…» — GPX (OsmAnd, Locus, Garmin) или KML
   (Organic Maps, Maps.me, Google Earth). Закрыли окно — трек забыт.
10. **Офлайн-пакет для телефона** — архив с отчётом, треками и **собственной офлайн-картой
    района** (MBTiles: дороги, тропы, вода, лес, рельеф и маршрут рисует сам QGIS).
11. **Публикует отчёт ссылкой** — на GitHub Pages в вашем репозитории, с QR-кодом для телефона.
12. **Поездка на несколько дней** по региону: 2–5 объектов, у каждого своя экскурсия,
    переезды между ними на машине в выгодном порядке, ночлег рядом с каждым и общий план
    по дням.

## Установка

1. Скачать архив `gis_tour_guide.zip` (или собрать: `python tools/build_zip.py` → `dist/`).
2. QGIS → «Модули» → «Управление и установка модулей» → «Установить из ZIP».
3. В меню «Модули» появится «ГИС-экскурсовод» и кнопка на панели инструментов.

Нужен QGIS 3.22 или новее и интернет. Ключи API не нужны — все источники открытые.

## Как пользоваться

Окно одно, сверху вниз:

**1. Объект.** Введите название и нажмите «Найти». Если мест несколько — выберите нужное
в списке «Найдено»; под ним видно, что это за объект и на какой тип туризма он похож.
Галочка **«Поездка на несколько дней»** открывает поле для ещё 1–4 объектов (по одному в
строке) — см. ниже «Поездка на несколько дней».

**2. Попутные объекты.**
* «Тип туризма» — автоматически, природный или городской.
* «Зона поиска» — ±N км от объекта до каждой стороны квадрата.
* «Сколько объектов» — сколько самых популярных отметить (3 — значит топ-3).
* «Подобрать попутные объекты» — плагин уточнит радиус («Ищем в ±15 км… Похоже, это
  городской туризм — обычно хватает ±1…3 км») и начнёт поиск.
* В списке «Посетить» поставьте или снимите галочки. Поменяли число объектов — галочки
  переставятся на новый топ без нового поиска; поменяли радиус или тип — подберите заново.
* «Варианты» — полдня / полный день / 2 дня с ночёвкой: щелчок ставит галочки за вас.

**3. Поездка.** Откуда ехать (пусто — региональный центр), кольцевой маршрут или в одну
сторону, дата и группа (для прогноза и расчёта воды и еды), рельеф (автоматически —
открытые тайлы высот, или ваш слой ЦМР, или без высот), подложка карты-схемы, что собрать.
Галочка «Сохранить фото в папку» — по умолчанию выключена: фотографии и так есть в отчёте.

**«Создать экскурсию»** открывает окно загрузки: все этапы списком, у каждого — отметка,
процент и время, сверху — общий ход, сколько прошло и примерно сколько осталось.
В «Подробностях» — журнал. Независимые запросы (описания, погода, фото, природа)
идут параллельно.

**Результат** появляется внизу окна: ссылка на HTML-отчёт (открывается в браузере) и кнопки:
* «Открыть PDF», «Папка», «Макеты карт»;
* **«Скачать трек…»** — GPX или KML (выбирается в окне сохранения). Кнопка становится
  активной сразу после построения маршрута — даже если карты или отчёт не получились;
* **«Офлайн-пакет»** — `<объект>_offline.zip` в папке экскурсии: `report.html`, `report.pdf`,
  `.gpx`, `.kml`, `.mbtiles` и `README.txt` с инструкцией. Organic Maps / Maps.me — откройте
  `.kml`; OsmAnd — `.gpx`, а `.mbtiles` скопируйте в `OsmAnd/tiles`; Locus Map открывает оба.
  Тайлов не больше 3000 (масштабы подбираются под размер района);
* **«Поделиться ссылкой»** — выкладывает отчёт на GitHub Pages и показывает ссылку и QR-код.
  Один раз нужно настроить (стрелка ▾ → «Настройки публикации»): публичный репозиторий
  (например, `tours`) и fine-grained токен GitHub только к нему с правами
  **Contents: Read and write** и **Pages: Read and write**. Токен хранится в зашифрованном
  хранилище QGIS. Pages обновляются 1–2 минуты.

### Поездка на несколько дней

Отметьте «Поездка на несколько дней», в поле поиска оставьте первый объект, а остальные
(до 4) впишите по строкам, например «вулкан Мутновский», «Долина гейзеров». Кнопка внизу
станет «Создать поездку». Плагин найдёт каждый объект, подберёт у каждого «Сколько объектов»
самых популярных попутных, выберет порядок с самыми короткими переездами (от регионального
центра или указанного места, по кругу или в одну сторону), построит экскурсии и ночлег у
каждого и разобьёт всё по дням с учётом светового дня. Получается:

```
<папка>/поездка_<объект>_<дата_время>/
  report.html, report.pdf   общий отчёт: карта поездки, итоги, план по дням, переезды,
                            объекты со ссылками на их подробные отчёты
  trip.gpkg                 переезды, базы, ночлег
  1_<объект>/, 2_<объект>/  полный отчёт и tour.gpkg каждой экскурсии
```

Трек «Скачать трек…» — один на всю поездку (переезды и все пешие маршруты). «Поделиться
ссылкой» выкладывает и общий отчёт, и отчёты объектов — ссылки между ними работают.
Офлайн-пакет делается для отдельной экскурсии.

### Что получается

В папке отчётов — только итог:

```
<папка>/<объект>_<дата_время>/
  report.html   отчёт: один файл, все карты и фото внутри — можно переслать
  report.pdf    тот же отчёт для печати (A4)
  tour.gpkg     все векторные слои и растр рельефа (таблица «dem»)
  photos/       только если отмечено «Сохранить фото в папку»
```

В проекте QGIS — группа «Экскурсия: …» с двумя подгруппами:
* **Векторные данные** — точки маршрута, фотографии, другие объекты рядом, маршрут,
  населённые пункты, дорога, ночлег, тропы, регион (всё из `tour.gpkg`);
* **Растры и подложки** — отмывка и раскраска рельефа (из `tour.gpkg`) и онлайн-подложки.

У слоёв «Точки маршрута» и «Фотографии» настроены подсказки (Map Tips): наведите мышь —
появятся фото и описание.

## Как это устроено

| Шаг | Источник |
|---|---|
| Координаты объекта, граница региона, название места старта | [Nominatim](https://nominatim.org) (OpenStreetMap) |
| Попутные объекты, населённые пункты и их население, региональный центр, плотность застройки, остановки, кафе, магазины, ООПТ | [Overpass API](https://overpass-api.de) (OpenStreetMap), резервные серверы mail.ru и kumi.systems |
| Описания, картинки, **популярность** (просмотры статей) | [Википедия](https://ru.wikipedia.org), Викиданные |
| «Как добраться», «Безопасность», «Где поесть» | [Викигид](https://ru.wikivoyage.org) |
| Дорога на машине и пешие маршруты | [OSRM](https://project-osrm.org) на серверах [FOSSGIS](https://routing.openstreetmap.de) |
| Рельеф | [Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) (AWS Open Data) или ваш слой ЦМР |
| Погода | [Open-Meteo](https://open-meteo.com) |
| Фото | [Викисклад](https://commons.wikimedia.org) |
| Животные и заметки туристов (природа) | [iNaturalist](https://www.inaturalist.org) |
| Подложки | OpenTopoMap, OpenStreetMap, CARTO Light |

* **Тип туризма** — по типу объекта (вулкан, пещера, водопад… — природа) или по числу
  зданий в 700 м (от 150 — город).
* **Популярность** — среднее число просмотров статьи в день за 30 дней; если статьи на
  русском нет — по числу Википедий, где об объекте написано. Тип объекта решает только
  при равенстве. В городе берутся объекты со статьёй в Википедии или Викиданных —
  иначе в центре Москвы были бы тысячи мемориальных досок.
* **Порядок обхода** — точная задача коммивояжёра до 12 точек, дальше — ближайший сосед + 2-opt.
* **Путь по рельефу** — A* по сетке высот, время шага — по функции Тоблера.
* **Время в пути** — по профилю высот; на осмотр: в природе ~25 мин на объект, в городе —
  по типу (музей ~1 ч 15 мин, храм ~20 мин, площадь ~15 мин).
* **Скорость подбора объектов**: OpenStreetMap спрашивается одним запросом (объекты,
  посёлки рядом, ООПТ, регион, застройка) и одним — про города региона; Nominatim, Overpass и
  Википедия опрашиваются одновременно. Если зеркало Overpass молчит дольше 7 с, параллельно
  спрашивается следующее; ответа ждём не дольше 45 с.
* Ответы сервисов кэшируются (`cache/gis_tour_guide` в профиле QGIS); если сервис недоступен,
  экскурсия всё равно строится, а в журнале будет предупреждение.

## Ограничения

* **Отзывы с TripAdvisor, Яндекс.Карт, 2ГИС и т. п. плагин не собирает**: открытого API нет,
  а автоматический сбор запрещён их правилами. Вместо них — подписи авторов фото Викисклада,
  Викигид и заметки iNaturalist.
* Путь по рельефу знает высоты, воду и болота из OSM, но не заросли и курумник. Участки
  «без троп» на карте отмечены пунктиром.
* Сезонность и часы работы — по тегам OSM; где их нет, плагин честно пишет «нет данных».
* Публикация ссылкой работает через GitHub Pages: для закрытого репозитория Pages доступны
  только на платных тарифах GitHub.
* В офлайн-пакете карта нарисована самим плагином по данным OSM — скачивать тайлы
  OpenTopoMap/OSM массово запрещено их правилами.
* Автомобильный профиль OSRM обычно не прокладывает путь по грунтовкам — «конец дороги»
  это конец дороги для легковой машины.
* Прогноз Open-Meteo — на 16 дней вперёд; для более поздней даты одежда подбирается по сезону.
* PDF собирается средствами Qt — оформление в нём проще, чем в HTML (без скруглений и теней).

## Для разработчиков

```
gis_tour_guide/
  planner.py   два шага без QGIS: collect() — попутные объекты, plan() — экскурсия; этапы для окна загрузки
  trip.py      поездка на несколько дней: порядок объектов, план по дням, общий GPX/KML
  outputs.py   слои, макеты и отчёты (главный поток) — для экскурсии и для поездки
  hours.py     разбор opening_hours: открыто ли в дату поездки
  trails.py    сеть маркированных троп, путь по ней
  offline.py   офлайн-пакет: своя подложка из OSM → MBTiles → zip
  publish.py   публикация на GitHub Pages, QR-код
  geocode.py   Nominatim + Википедия, граница региона
  osm.py       Overpass: категории для природы и города, население, региональный центр,
               плотность застройки, транспорт, кафе, магазины, ООПТ; выбор точки старта
  wiki.py      Википедия (описания, популярность), Викигид, Викиданные, Викисклад
  routing.py   OSRM: машина, пешеход, сводка по дорогам, участки без троп, маркированные тропы
  terrain.py   тайлы высот (параллельная загрузка), профиль, Тоблер, путь по рельефу (A*) с маской воды
  tsp.py       порядок обхода
  extras.py    погода, iNaturalist, опасные животные
  advice.py    советы для природы и для города
  report.py    фирменный отчёт HTML/PDF, GPX, профиль высот, фото в памяти
  webmap.py    интерактивные карты HTML (vendor/leaflet — Leaflet 1.9.4, BSD-2)
  schedule.py  оценка времени, разбивка по дням, варианты «полдня / день / 2 дня»
  maps.py      слои, GeoPackage (векторы + растр), фирменные стили, три макета
  brand.py     фирменные цвета и стиль окна
  progress.py  окно загрузки
  widgets.py   выпадающий список с галочками
  dem_layer.py высоты из слоя ЦМР проекта
  task.py      фоновые задачи QgsTask
  dialog.py    окно плагина
```

Тесты (без сети — ответы сервисов подделаны в `tests/fake_services.py`, два сценария:
вулкан Горелый и Московский Кремль):

```
python -m unittest discover tests      # test_pipeline.py — нужен Python из QGIS (модуль qgis)
```
